## 1. Executive Summary & Existing Architecture Audit

StepSheet is a high-performance Windows desktop and portable spreadsheet application combining an Excel-replica grid, a recorded-step transformation engine (Power Query-style), and a full-featured visual dashboard suite.

```json

  "schema_version": "1.0",
  "intent": "aggregation",
  "dataset_id": "active_dataset",
  "select": [
    {"column": "Region", "aggregation": null, "alias": "Region"},
    {"column": "Sales", "aggregation": "sum", "alias": "Total Sales"}
  ],
  "filters": [
    {"column": "Sales", "operator": "gt", "value": 0}
  ],
  "group_by": ["Region"],
  "sort": [{"column": "Total Sales", "direction": "desc"}],
  "limit": 10,
  "chart": {
    "type": "bar",
    "x": "Region",
    "y": "Total Sales"
  },
  "explanation": "Total sales grouped by region, sorted descending.",
  "assumptions": ["Null sales values excluded"]
}
```

## 5. Security, Privacy & Reliability Controls

1. **Zero Raw Dataset Transmission**: LLM prompts receive strictly column names, detected data types, row count, null percentages, and bounded summary statistics (min/max/cardinality). Raw dataset rows are never transmitted to any external API.
2. **Strict Parameterisation & Allowlisting**: All plan objects are validated against the dataset's actual schema before DuckDB execution. Table and column identifiers are escaped with double quotes (`"column"`). Filter operators are restricted to `['eq', 'neq', 'gt', 'gte', 'lt', 'lte', 'contains', 'is_null', 'is_not_null']`.
3. **Prompt Injection Boundary**: Schema metadata is wrapped in `<data_context>` XML delimiters with explicit instructions to treat cell contents as untrusted literals.
4. **Zero-API-Key Local Runtime**: Local Ollama execution runs on loopback `127.0.0.1:11434` without requiring any cloud API key or external network communication.

## 6. Phased Implementation Sequence

- **Phase 1: Local AI Runtime & Hardware Management (Section 19)**
  - Create `apps/api/app/services/ollama_manager.py` (hardware profiler, service lifecycle, model catalog, streaming download, health check).
  - Add API endpoints in `apps/api/app/api/v1/endpoints/local_ai.py`.
  - Add frontend `LocalAiSetupModal.tsx` and status indicators.
- **Phase 2: Feature A — Chat with Data**
  - Create `apps/api/app/schemas/chat_query.py` and `apps/api/app/services/chat_query_service.py`.
  - Add API endpoint `POST /api/v1/ai/chat-query`.
  - Create `ChatWithDataModal.tsx` in frontend and wire "Ask AI" in ribbon and task pane.
- **Phase 3: Feature B — Native Julius-Style Plain-Text to Interactive Dashboard**
  - Create `apps/api/app/schemas/ai_dashboard.py` and `apps/api/app/services/ai_dashboard_service.py`.
  - Add API endpoint `POST /api/v1/ai/generate-dashboard`.
  - Integrate "Create Dashboard with AI" bar in `DashboardModal.tsx`.
- **Phase 4: Conversational Dashboard Editing**
  - Implement `POST /api/v1/ai/patch-dashboard`.
  - Add conversational refinement prompt bar in `DashboardModal.tsx`.
- **Phase 5: Automated Testing, Single-File Packaging & Deliverables**
  - Add comprehensive Pytest and Vitest test suites.
  - Rebuild portable `StepSheet.html`.
  - Generate release documentation.
